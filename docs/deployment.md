# Windows 部署、安全与备份

## 构建与交付

开发和打包需要 Windows x64、Node.js 22.x 与 .NET 8 SDK。安装依赖后可运行 `npm run build` 构建服务和网页，运行 `scripts\启动.cmd` 启动开发构建。

`node scripts/build-release.mjs` 会清理旧的服务和网页输出，在空的 `release-staging` 中重新发布 Claude 原生宿主与托盘启动器，并复制发行所需的 Node.js 运行时和依赖。目标平台为 win-x64；所有关键文件验证成功后才替换 `release`，上一版保留为 `release-backup`。发行包不得包含数据目录、`.env`、数据库、token、日志或 Claude 登录凭证。

系统支持后台自动处理和可见 Claude 终端两种执行方式。问题审核同意后才调用本机 Claude；只有完整成功结果且进程正常退出才进入答案审核，可见终端以 Bypass Permissions 权限启动，本轮完成后自动退出回传，无需手动输入 `/exit`。客户只有在管理员同意发布后才能读取答案。升级保留账号、项目、网络配置和历史；独立窗口、Windows 通知和其他设备访问仍应在实际部署环境中验收。

## 数据与网络

管理端启动不依赖客户入口监听成功。客户地址不属于本机、客户端口冲突或未授权内网监听时，服务保留本机管理入口，设置页显示客户入口失败原因。管理员可修改配置并从托盘停止、重新启动服务；修正前不提供可用客户地址，也不会自动改写原配置。`connection.json` 的 `clientUrl` 仅在客户入口实际监听成功时为地址，失败时为 `null`，`clientError` 保留启动原因；`adminPort` 与 `pid` 仍供托盘打开管理台及轮询。

默认数据目录 `%LOCALAPPDATA%\ClaudeBusinessDesk`，可由 `DESK_DATA_DIR` 覆盖。服务配置以 JSON 值持久化在 SQLite `settings` 中，无独立 config 文件，并通过管理员 API 管理设置；launcher 不另造配置源或覆盖公司设置。固定业务提示词 `fixedPrompt` 与附加指令 `extraPrompt` 在设置页分别编辑并持久化，保存后对下一次新提问及追问生效，无需重启；旧数据缺少 `fixedPrompt` 时沿用原默认提示词。端口设置变更需重启服务；管理员提醒方式 `adminNotificationMode` 只有 `window` / `notification`，旧数据默认独立窗口，保存后下一轮轮询生效。令牌 `launcher.token` 留在该目录，只供本机通知查询，限制目录 ACL，勿放到共享盘或日志。服务启动写入该目录 `connection.json`，格式 `{adminPort,clientUrl,pid}`。启动器每轮读取，验证端口在 1–65535 且 PID 匹配自己拥有的后端，再构造 `127.0.0.1` 管理端/事件地址；缺失或无效时等待服务连接信息，不猜测端口。打开管理端、复制客户地址也刷新该记录，不会把 launcher token 发到记录指定的其他主机。客户端监听 `0.0.0.0` 时服务提供本机 LAN 地址，而不是不可用的 `0.0.0.0`；多网卡环境需管理员确认员工可达地址。

管理端默认 localhost:4310，客户默认 localhost:4311。服务额外占用仅本机的 127.0.0.1:4309 作为内核管理的单实例保护端口，防止陈旧 PID 锁接管竞态；该端口不可作为网页端口，若被其他程序占用则拒绝启动，不修改数据库执行状态。loopback 地址不能供其他员工设备使用。需要 LAN 时，管理员必须在管理设置里显式确认 `allowInsecureLan` 后再改监听地址，或配置内网 HTTPS 反向代理；优先后者。具体设置名称以服务实现为准。HTTP LAN 流量可能被同网段设备观察/修改。内网 HTTPS、证书、DNS、代理信任、访问控制与防火墙均由管理员配置，脚本不自动修改防火墙，不声称自动获得 HTTPS。

不要暴露管理端到公网，不将本地 token 交给客户浏览器。发行时只发送 release，不发送数据目录、`.env`、本机 Claude CLI 配置或凭证。包内完整 node_modules 可能含开发依赖，管理员应做许可证与供应链检查。

## Claude 与公司数据

实际 Claude 运行依赖主机上的 CLI 安装和该主机用户登录；发行包不分发 CLI 登录凭证，不复制个人会话，不保证已登录。模型调用可能收费，管理员应确认账户、额度与权限。

使用正常项目说明、Skills、插件、MCP 与 hooks。每次新提问、追问及重试都拼入不可被业务设置替换的只读问答提示规则，要求只查询、分析和解释，拒绝新增、修改、删除业务资料、执行变更和提交外部操作。每轮还追加纯业务回答要求，不输出代码、源码位置和无关技术细节；发布接口拦截明确的代码块、源码文件/行号引用和常见执行语句，待管理员改为业务说明后发布。该规则仅约束模型行为，MCP 等现有能力继续保留，不保证恶意输入无法绕过；提示不是访问控制或 OS 沙箱；现有扩展仍可能读写文件、运行命令、访问网络。不得批准不可信项目。后台模式固定使用 print/stream-json、Claude `auto` 权限分类和无交互权限提示；仍需人工批准的动作失败后应改用终端模式。终端模式按管理员要求使用 `bypassPermissions`，通过 `--permission-mode bypassPermissions` 显式启动，首次提问和恢复追问都一致；CLI 仍负责组织策略、显式规则和启动前确认，在核验同一 session、原问题、end_turn、完整转录的结束标记、Stop hook 和最终正文一致后，自动发送退出指令；进程自然退出成功才回传答案，管理员无需手动退出。接口错误通过 StopFailure 提前报告，其他 hooks 继续执行时等待完整结束。后台固定使用 `auto`；可见终端固定使用 `bypassPermissions`。固定及附加指令保留默认系统提示，保存后仅新调用生效。正常结束或取消后，JobObject 清理仍持有输出管道的子孙进程，避免队列永久等待。

密码仅要求非空（上限 128 字符），请用强密码并限制管理端访问。Claude 程序和项目目录在页面填写完整本机路径，保存时仍需校验。只保留新问题审核、答案审核、客户网页回复提醒三类弹框；其他操作和错误在页面展示，启动器故障记入数据目录的 launcher.log 和托盘状态。

公司输入、附件及必要上下文会发送到模型提供方，部署前需获得公司与数据所有者授权，确认适用的数据处理、留存与跨境政策，避免提交未授权秘密。不得保证可读取或展示模型内部思考。应用权限与进程 JobObject 不是 OS 沙箱，也不保证免受网络攻击或 DDoS；隔离、网络限流、监控及备份由管理员安排。

## 连续对话与数据升级

连续追问使用当前客户、业务对话及项目的已发布 Claude session ID，通过 `--resume` 恢复原生工具上下文，同时附上应用冻结的正式问答，确保管理员编辑后的答案优先。后台与可见终端均采用明确会话 ID，不使用 `--continue`。执行开始即使该会话暂时不可复用，只有答案发布后才恢复可复用标记；失败、取消、答案拒绝、目录变更或旧版本缺少会话 ID 时，下一轮仅用已发布历史创建新会话，排除未发布内容。每轮提交冻结历史文本与来源，双审核不变；新对话不带旧历史。同一客户仍仅一条活跃问题。会话固定客户和项目，读历史、追问和执行前均检查当前授权。拒绝/失败/取消轮可作为时间线终态显示，不回放到模型历史；只有最新失败/取消轮可重试。

升级通过事务迁移给每条旧问题建立独立业务对话，不把无关旧问题自动合并。备份前后应核对账号、授权、问题数和状态。未知更高数据库版本拒绝启动，不强行降级。导出包含新的对话结构及逐轮快照，仍含敏感业务数据。

数据库升级到版本 3，增加账号独立的记录删除状态和每段业务对话的可恢复 CLI session。已有用户、授权、问答、归档和配置保留；版本 2 的历史首轮追问会用已发布问答重新建立 CLI 会话。

问答记录按对话展示，原问题及追问合并为一条卡片，按顺序显示各次追问及每轮独立状态，并汇总可见轮数、追问次数和最新状态；详情以时间线标记首次提问及各次追问，状态紧邻轮次编号。工作概览的最近业务问答使用相同对话卡片并支持直接打开详情。管理端和客户均支持删除整段对话、多选对话和清空，详情还支持逐轮删除和多选轮次。删除仅影响当前登录账号的列表及详情，其他管理员或客户的记录独立保留，客户无权操作其他用户的历史。清空覆盖全部分页，只移除预览时间前已结束的记录，正在处理或预览后更新的轮次保留；实际范围变化需重新预览。原始问答、上下文快照、运行与审计不从数据库物理删除，后续追问及管理员导出、SQLite 备份仍保留完整依据。旧日期清理接口和设置入口已移除。

## 一致性备份与恢复

SQLite 可能使用 WAL。运行中直接复制主 `.sqlite` 文件会漏掉尚未 checkpoint 的事务；不要把这种拷贝称为一致性备份。

管理员应通过已认证的 `GET /api/backup` 下载服务返回的 SQLite 快照（服务负责 WAL 一致性），用管理员登录会话访问，禁止用 launcher token 替代管理员凭证。保存到受访问控制的备份位置，记录时间并定期测试恢复。SQLite 快照包括数据库内的 `settings` JSON 设置；必要的其他数据资源也须单独安全备份。服务通过 Node 内置 `node:sqlite` 的 backup 实现快照。Node 22.22 的该模块仍为 experimental，可能输出实验性警告，但不需要原生 SQLite npm 依赖。不要公开备份、令牌或登录信息。

恢复前停止后端并保留当前数据副本；按服务实际数据库文件名恢复快照，处理旧 WAL/SHM 时遵循数据库恢复流程，避免将不匹配的日志与新快照混用。恢复后验证权限、数量和关键业务记录。自动化测试已检查备份可独立打开并包含历史和配置；实际生产备份恢复仍需定期演练。

## 验收清单

1. Windows 中文/空格目录启动、正常退出和错误提示；4310/4311 不意外监听公网。
2. 托盘停止/退出及后端异常退出后，所有子孙进程退出；启动器被终止时 Job 清理。
3. 管理台设置仅提供独立审核窗口或 Windows 通知；Windows 通知正文和按钮均打开管理员审核页，系统禁用通知时在托盘和日志提示。已处理通知清理，强制结束启动器可能留下旧通知至一天有效期结束，点击仍按当前状态审核。token 无效时 events 拒绝；令牌不出现在命令行/日志或 WebView2。启动时已有待审核问题也入队，按 ID/审核阶段/更新时间去重，数量减少不弹。token 接口仅返回待办身份，正文与同意/拒绝必须使用管理员登录及 CSRF。WebView2 限制同源导航、下载与权限，缺 Runtime 时在当前审核窗显示说明和手动打开浏览器按钮。
4. LAN 的显式确认和 HTTPS 代理，以及管理员/客户权限隔离。
5. Claude 主机登录、真实调用授权/费用，以及备份恢复流程。
