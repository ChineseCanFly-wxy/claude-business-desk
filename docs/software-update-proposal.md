# 工作台新版提醒与点击更新方案

状态：方案评估，尚未实现。范围：Windows 工作台软件的正式版本更新。

用户期望：有新版时提醒，用户点击后更新。

## 使用流程

1. 托盘启动后在后台检查新版，之后每 6 小时检查一次；管理台和托盘提供“检查更新”入口。
2. 发现更高的正式版本后，托盘提醒一次，管理台显示当前版本、新版版本号和更新说明。
3. 用户选择“立即更新”或“稍后”。选择“稍后”保持当前版本，同一版本本次运行不反复弹提醒。
4. 点击更新后下载完整 Windows ZIP 和对应 SHA-256 校验文件，界面显示进度。
5. 下载及校验完成后检查是否有运行中任务。有任务时显示“等待当前任务结束”，允许取消。
6. 准备安装时暂停接收新问题和启动新任务，确认运行中任务已经结束，再备份并更新；待审问题和已排队问题继续保留。
7. 新版启动并通过本机检查后恢复服务，显示“已更新”。失败则恢复旧程序及对应数据备份，显示失败原因。

检查更新连不上 GitHub 时，工作台继续运行。手动检查时显示失败信息，自动检查时后台重试；公司 VPN 的连接流程保持原样。

## 现有基础与改动范围

可行，整体属于中等改动。仓库的标签工作流已经生成正式 Release、`claude-business-desk-vX.Y.Z-win-x64.zip` 和 `.sha256`，发行包内已有 `package.json` 版本号。数据目录独立于程序目录，有利于保留账号、配置、问答和附件。

需要补充四部分：

| 部分 | 内容 |
|---|---|
| 版本检查 | 查询固定仓库的正式 Release，按语义版本比较；跳过草稿、预发布、相同及较低版本 |
| 提醒界面 | 托盘通知、管理台更新卡片、手动检查、下载进度和稍后处理 |
| 更新安装 | 下载到临时目录、核对 SHA-256、检查 ZIP 路径和完整性，由外部更新助手等待进程退出后替换程序 |
| 数据与恢复 | 阻止安装期间新任务启动、关闭数据库连接、保存数据库和附件备份、检查新版启动及超时恢复 |

版本信息通过 [GitHub Release 官方 API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release) 获取。查询公共仓库的正式版本无需保存个人 GitHub 凭据。下载地址和重定向限制在 GitHub 官方资产域名，更新包检查版本号、平台和必需程序文件。

更新助手在程序目录之外运行，保留旧程序目录后再切换。若数据库结构发生升级，回退须同时恢复更新前数据库和相关附件；新版验收完成前保持客户写入暂停，避免回退丢失新提交。数据库、附件、自定义数据目录及 Claude 登录状态都必须保留。更新目标固定为当前安装目录，不沿用 ZIP 内的任意绝对路径。

## 验收重点

- 新版仅提醒一次；“稍后”继续使用，手动检查可再次打开更新提示。
- 相同版本、预发布、网络失败和 GitHub 限流均不影响原工作台。
- 校验失败、包损坏或目录无权限时保留当前程序。
- 运行中任务不被强行停止；安装开始后不能再启动新任务。
- 更新后保留账号、设置、免登录偏好、历史问答、附件和待审事项。
- 新版启动失败时恢复旧程序及匹配的数据，客户入口和审核恢复正常。

首版即实现完整的“提醒 → 点击下载 → 安装并重启”流程，具体发版继续遵循 `docs/RELEASING.md`。
