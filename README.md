# 沐雨橙风 · Claude Business Desk

本项目采用 [MIT License](LICENSE) 开源。推送到 `main` 后，GitHub Actions 会在 Windows 上完成类型检查、测试和完整打包；构建完成后可在对应 Actions 任务的 Artifacts 中下载 `claude-business-desk-win-x64-<commit>`。

Windows 本机业务问答工作台。管理端默认 `http://localhost:4310`，客户入口默认 `http://localhost:4311`。客户默认仅本机访问；用于公司内网前须配置监听地址与网络安全。

## 使用流程

1. 打开管理页面创建管理员。密码非空即可，无复杂度要求，最多 128 字符；所有密码框支持小眼睛显示/隐藏。建议实际部署仍使用不易猜测的密码。
2. 在设置中填写本机 Claude Code 原生 `.exe` 的完整路径，检测安装；创建项目时填写项目目录的完整路径。
3. 创建客户账号、授权项目。没有公开注册。
4. 在工作台设置中分别选择管理员提醒方式和 Claude 执行方式。提醒只有独立审核窗口（默认）或 Windows 通知；执行只有后台自动处理（默认）或可见 Claude 终端。问题通过审核后，后台模式自动运行；终端模式打开原生 Claude 对话，可现场处理工具授权，回答及 hooks 完成后输入 `/exit`，系统自动核验并收取答案。两种方式最终都进入答案审核，不另设“收取答案”弹框。
5. 正式答案发布后，客户网页弹出“你的问题已回复”，只展示原问题，点击“查看回复”在对话中读取完整答案。第一次使用此浏览器时历史不弹；已有浏览器再次打开或登录时会补提醒离线期间尚未确认的新答复，点击查看或关闭才算确认。关闭网页时不提供系统通知。每位客户跨项目仅允许一个未完成问题，Claude 全局串行排队。
6. 答案已发布，或本轮已拒绝、失败、取消后，客户可在当前对话“继续追问”，也可“开启新问题”。Claude 已返回但管理员尚未发布时仍是待审核，不能提前追问。后台同步不会清空正在输入的内容；同步失败在页面提供“重试同步”，提交错误保留到下一次提交或切换对话。每轮追问仍需双审核；对话固定同一项目，历史保存全部轮次与状态。开启新问题不会取消正在处理的问题，也不会绕过单用户未完成限制。

连续追问使用应用保存的此前已发布完整问答，包括管理员编辑后的最终答案；提交时冻结业务历史，审批、排队及重试沿用这份快照。拒绝、失败、取消轮仍显示在界面，但不将这些轮的问题、拒绝理由或未审草稿放入模型历史。每轮真实调用创建新的原生 CLI session，不恢复含有未审内容的终端 session，所以这里的连续上下文是已发布业务问答，不包含旧会话全部内部工具输出。新对话不含旧对话历史。

上下文不会静默截断或自动摘要；接近输入/Windows 命令行上限时会在页面提示开启新问题。问题经 UTF-8 管道传入，业务指令仍受命令行长度限制；这些上限不等于模型 token 上限。附加业务指令采用执行时已保存的配置，项目文件和 CLI 配置并不被冻结。只有最新失败/取消轮可以重试，已有后续轮次的旧轮不能倒序重试。

管理页面不再展示执行记录和原始日志。数据库仍保留内部调用与审计记录，管理员导出与备份仍包含这些信息，请妥善保管。

## Claude 执行方式与业务指令

后台自动处理使用 Claude Code 的 print/stream-json 和 `auto` 权限分类；安全动作由 Claude 自动判断，需要人工确认或被明确禁止的动作仍会失败，并提示切换到可见终端。可见终端使用原生交互会话和 `manual` 权限模式，管理员只处理本轮权限提示，不应追加新的业务问题；回答完成后输入 `/exit`。系统再核验会话、原问题、完整结束状态、Stop hook 与最终正文，核验通过才送入答案审核。两种方式都明确覆盖本机可能配置的跳过权限模式，绝不使用 `bypassPermissions` 或危险跳过参数。

两种方式均保留本机登录和正常项目说明、Skills、插件、MCP 与 hooks。后台输出采用结构化结果，终端输出采用 transcript 和 Stop hook 交叉验证，不抓取 ANSI 屏幕文字。失败、权限拒绝或超时只在页面显示处理状态；取消和退出时由 JobObject 清理整个子进程树。执行方式只影响随后开始的任务，不改变正在运行的任务。

固定业务指令与附加业务指令通过 `--append-system-prompt` 追加，保留 Claude 默认提示。设置页可预览组合内容；保存后对后续新调用生效，不改正在执行的会话。现有扩展可能运行命令和访问网络；只批准你信任且获授权的项目和环境。本工具不是 OS 沙箱。

## 启动与发行包

已有发行包时双击 `release\ClaudeBusinessDesk.Launcher.exe`。托盘负责启动/停止服务、打开管理端、复制客户地址和退出。管理员可在设置中选择独立 WebView2 审核窗口或 Windows 通知，需要管理员登录审核；关闭、稍后处理或点击通知不代表同意或拒绝。启动时已有待审核问题也会提醒，按身份、审核阶段和更新时间去重；独立窗口每次只显示一个。切换提醒方式清空尚未打开的窗口队列，已打开窗口保留未保存编辑。已处理的通知从通知中心移除；系统通知被禁用时托盘提示不可用，详情写入日志，待办保留在管理页面，不额外弹窗。除问题审核、答案审核、客户回复提醒外，账号、项目、详情、错误和取消操作均在页面内处理；启动器错误写入数据目录的 `launcher.log` 并更新托盘状态，不弹消息框或气泡。

Windows 通知由桌面启动器接入系统通知中心，不依赖内网 HTTP 网页的通知权限。客户只需登录网页提问和查看回复，网页关闭后不接收新消息；再次打开时补上未读答复。客户没有常驻程序、Web Push 或通知权限申请。浏览器自身限制普通内网 HTTP IP 网页使用系统通知，这不是项目添加的限制。

普通“问答详情”只从管理端“问答记录”打开。工作概览只展示摘要；客户对话本身已经展示完整问题和正式答案，不再重复打开详情。审核收件箱和启动器审核页继续展示审核所需内容及同意／拒绝操作。

Claude 路径可以暂时留空，先保存提醒方式或网络配置；真正执行问题前再配置本机 CLI。

管理端独立绑定本机地址。客户监听地址失效、端口被占用或未获内网监听授权时，管理端仍可启动；进入“工作台设置”查看原因、修改客户地址或端口，保存后从托盘停止并重新启动服务。客户入口未启动时，托盘会解释原因，不复制不可用的客户地址；程序不自动改写已保存的网络配置。

WebView2 Runtime 是审核窗口的运行前提；缺失时在当前审核窗说明原因，并提供手动打开本机浏览器审核页的按钮。发行包自带 Node 和 .NET 运行时，但不包含 Claude Code 或其账号凭证。

开发运行：

```powershell
npm install
npm run build
# 原生程序只需构建一次，修改后再构建
 dotnet publish apps/native-host/ClaudeTerminalHost.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o dist/native
.\scripts\启动.cmd
```

每次发行都运行同一条命令；脚本会先清理旧的服务与网页构建，再重新编译服务、网页、Claude 原生宿主和启动器：

```powershell
node scripts/build-release.mjs
```

打包脚本需要 x64 Node 与可用的 .NET SDK；它会清空 workspace 内固定的 `release-staging` 目录，在其中全新发布 Claude 原生宿主和启动器并组装完整发行包，成功后才替换 `release`；切换失败会尝试回滚，上一版保留在固定的 `release-backup`。脚本不复制用户数据、`.env`、token、SQLite 数据库或 Claude 凭证。仅分发检查后的发行包。

## 数据与验收边界

升级保留内部标识和 `%LOCALAPPDATA%\ClaudeBusinessDesk` 数据目录，账号、项目与历史不因改名迁移。可用 `DESK_DATA_DIR` 指定其他数据位置；配置保存在 SQLite 中，监听端口变更需重启。不要运行时覆盖数据库。

验证命令：`npm run typecheck`、`npm test`、`./scripts/check-notifications.ps1`、`npx tsx scripts/native-smoke.ts`。通知静默检查验证内容、链接、去重与模式切换，不注册或发送系统通知，不显示窗口。最后一项只使用本机测试进程验证 UTF-8、自动完成和子进程清理，不调用模型。`npx tsx scripts/smoke-claude.ts` 使用临时合成资料真实调用本机 Claude，可能产生模型费用；浏览器与原生窗口、另一台设备访问应按实际部署环境验收。

部署、授权及一致性备份详见 [部署说明](docs/deployment.md)。
